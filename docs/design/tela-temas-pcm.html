As 3 subtarefas da base entram sozinhas no fim de todo tema

O que esta tela resolve. Hoje os temas moram em os_creator/solic_spec.py, num dicionário Python. Mudar o nome de um tema, acrescentar uma subtarefa ou marcar anexo obrigatório significa editar código e subir release. Aqui isso passa para a mão do PCM.

Decisões que precisam da sua palavra antes de eu construir:

  1. Onde os temas ficam salvos. Hoje são código. Se virarem dado editável, precisam de um lugar — arquivo local (só vale para quem editou), banco da Gridco (vale para todos, mas depende da API estar no ar) ou o próprio Fracttal. Recomendo o banco, com o código atual servindo de valor inicial: sem isso cada PCM teria um conjunto diferente de temas.
  2. Quem pode editar. Se qualquer um mexe, um tema errado contamina toda OS criada depois. O app já é multiusuário e sabe quem entrou.
  3. O que acontece com as OS já criadas. Nada — a OS leva as subtarefas copiadas no momento em que nasceu. Editar um tema muda só as próximas. Vale deixar isso escrito na tela.
  4. As 3 subtarefas da base (descrição, registro fotográfico, pendência) entram no fim de todo tema, e hoje não são editáveis. Deixo assim?

O que não desenhei de propósito: excluir tema. Um tema já usado em 751 solicitações não pode simplesmente sumir — o certo é arquivar, e some da lista de escolha sem quebrar o histórico. Se você concordar, acrescento.
